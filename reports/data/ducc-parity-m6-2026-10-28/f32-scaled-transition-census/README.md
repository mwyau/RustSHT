The diagnostic hardware-normal bound accepts any finite normal f32 state (or zero); it is a coverage bound and was not used by the current fused kernel. Each route also records later state declines. The reported suffix coverage counts only blocks whose recurrence states stayed within the selected bound through the final degree; speculative work counts state-bound contributions through the first decline. This is recurrence-state potential only, not fused-kernel eligibility: coefficients, contributions and accumulated outputs have not been checked. A matching q1 census and output-safety route counts are still required before choosing or implementing the candidate.

## Later real-state correction

A q1 full-mmax replay at newer production source `54b166f2` captured nonzero state values with exponents from `-160` to `-320`; applying those exponents turned the states into zero while scaled coefficient products remained nonzero. An isolated underflow guard then completed no nonzero-exponent suffix packets. This demonstrates why the earlier “normal-or-zero” state test overstates safe transition coverage. Keep the raw potential counts above for historical context, but do not use them to justify a production suffix handoff. The corrected route counts, packet values, and patch are in the linked [real-state replay](../f32-exact-zero-operand-suffix-rejection/README.md).
