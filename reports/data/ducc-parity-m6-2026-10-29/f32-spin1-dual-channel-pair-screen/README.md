# T720 f32 spin-1 fused scalar-pair screen — rejected

This is a bounded Stage D screen against exact source parent 07193db72933ea7ecb914986874fa1219a3629d4. No production code was promoted. The candidate used a shared f64 scalar recurrence to accumulate two spin-converted scalar channels together behind the existing public f32 spin-1 synthesis call. The intended benefit was one reflected recurrence pass instead of two f64 scalar transforms.

The parent is the recovered two-call f32-I/O/f64-internal adapter patch (b78a1ef88e7d829b9980eb7c96da87fe17c7809a215ab985598d0c3ba32a3eac). The candidate source-only patch is 76,570 bytes, SHA256 4db18542074bd5b23ee1e5b70b6c17e6ae9862656ff319f2d3977fd5b761e7cd; it retains the shared FusedSynthesisBlock, paired recurrence visitor, and F32SynthesisAccumulator owners. The initial recovered two-call adapter is also present as a patch. The candidate patch is retained for diagnosis and replay, not promotion.

Pinned DUCC was 0.42.0 commit 42ce8ab5c5d79e0e2fd9af4a09c2ea4693520e1b. Rust used rustc 1.99.1, LLVM 23.1.1, -C target-cpu=x86-64-v3 -Aunexpected_cfgs; DUCC used GCC 15.2 with -O3 -ffast-math -ffp-contract=fast -march=x86-64-v3, while its driver used -fno-fast-math. q1 was pinned to one logical CPU; q8 to eight distinct physical-core threads, fixed identically across all arms. Warm plan/workspace setup was excluded; each worker included the full public f32 transform and used a 25 ms warm-call target. Fixtures were generated by scripts/benchmark_ducc_f32_native.py::make_fixture with phi0=0.23.

## T720 public f32 spin-1 synthesis

Each cell has three interleaved parent/candidate/DUCC comparisons. Three pairs were sufficient to reject q8 because every candidate q8 comparison was slower than the parent and well over DUCC. q1 cells were not extended: their candidate did not establish a repeatable improvement over parent, and q8 failed decisively.

Candidate-vs-DUCC relative L2 error was at most 3.9061e-8 and maximum absolute error at most 1.1921e-7. Every worker reported finite output, repeated-call consistency, and poisoned-output reset. These checks do not establish independent correctness for production because this route failed the performance gate.

The current f64 general-spin route through complete f32 I/O was included as a fourth q8 reference. Full q8 medians were 17.509 ms fused pair, 10.529 ms f64 general, and 7.453 ms DUCC; the fused pair was 1.724x f64 general and 2.349x DUCC. Reduced q8 medians were 7.580 / 3.816 / 3.203 ms, or 1.892x f64 general and 2.366x DUCC. Thus the fused two-channel implementation is slower than simply calling the current shared general f64 route.

## Mechanism and memory

One warmed full q1 transform was profiled with Callgrind. Total Ir rose from 575,866,983 parent to 735,121,633 candidate (+27.7%). With --inclusive=no, parent synthesize_range_dispatched accounted for 306,997,576 Ir (53.31%); candidate synthesize_ordinary_suffix_vector_pair::<pulp::x86::v3::V3> accounted for 415,481,376 Ir (56.52%). Ir is instruction references, not elapsed cycles. The candidate AVX2/V3 function grew from the parent's 0x50c-byte suffix to 0x808 bytes. Source and disassembly show repeated coefficient-slice bounds checks in the degree loop and YMM stack spills/reloads; the parent loop keeps recurrence and sums in registers. This explains the q8 loss and makes the new suffix a poor bulk path.

Massif q8 full-process peaks were 90,849,936 bytes parent and 99,401,816 bytes candidate, a delta of 8,551,880 bytes. This is total process heap at peak, including fixture/output buffers, plan, and reusable workspaces; it is not a workspace-only measurement. A separate global-allocator counter around one warmed public transform measured zero allocation calls, zero requested bytes, and zero freed bytes for both parent and candidate. The buffers causing the peak are therefore reusable setup storage, not per-call allocation churn.

## Correctness scope and conclusion

The focused route test reflected_scalar_pair_matches_two_independent_t720_syntheses passed for full/reduced and q1/q8. The public f32 route test f32_t720_spin_synthesis_uses_checked_internal_pair_route passed for full/reduced and q1/q8. cargo check --release --features parallel --lib passed. The benchmark workers passed finite, repeat, and poisoned-workspace reset checks. The candidate was not run through the full analytic, adjoint, extreme/subnormal, tail, and independent reference matrix because q8 performance rejected it.

Keep this as a quantified rejection. Continue Stage D with a native-f32 dual-channel reflected accumulation leaf through the existing hemisphere scheduler, using the shared typed recurrence and checked fallback, and verify q1/q8 route counters. The current f64-internal general route is an available fallback hypothesis for analysis, but q8 spin synthesis is still 1.19–1.41x DUCC and the fused scalar-pair adapter is slower.
