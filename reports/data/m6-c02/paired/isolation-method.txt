M6 C02: `recombine_half` guard isolation
Captured: 2026-10-17 UTC

Design
- Built `target/m6-c02-no-guard-bench` from the C02 candidate source using `cargo build --release --example m1b_bench`. The diagnostic-only edit removed the `recombine_half` finite-result branch and exceptional half-sum fallback, returning its original ordinary expression. All other source, including `inverse_series` and its normalization path, was unchanged. The edit is recorded in isolation-no-guard-diff.patch. The exact `src/fft.rs` was copied to src-fft-before-no-guard.rs and restored immediately after the build; its restored SHA-256 is 3c99bd7d84267c84167a0574a42979136c9c6228e8563e8430cf95084e0d83ec.
- Binary hashes, C02 patch hash, and command are in isolation-binaries.txt. The build emitted only an expected unused `half_sum` warning because the diagnostic branch was removed.
- Measured three fresh-process triples for scalar T255 q1 and spin-1 T511 q1. Each uses GL STANDARD f64, ntheta=T+1, nphi=2(T+1), mmax=T, phi0=0.37, both operations, requested-only mode, CPU 0. Order rotated across triples: baseline/candidate/no-guard; candidate/no-guard/baseline; no-guard/baseline/candidate. Every process retained the harness's five timed samples per operation and was measured with `/usr/bin/time` for elapsed time and peak RSS. Raw outputs, time files, and per-process preflights are retained.
- All 18 per-process snapshots exist, no contention flag was raised, and no compiler, benchmark or FFT workload was seen. Load averages were 0.33-0.38 (1 min), 1.85-1.87 (5 min), and 2.46-2.47 (15 min).
- isolation-summary.csv reports medians over three processes and paired ratio medians/ranges across the three triples. `both` is synthesis plus analysis per-process medians. This is a small diagnostic screen and has no bootstrap interval or acceptance conclusion.

- Spin-1 T511 q1: synthesis 42.260 / 41.827 / 41.609 ms; ratios 0.9895 / 0.9908 / 0.9864. Analysis 27.426 / 27.829 / 26.940 ms; ratios 1.0147 / 0.9707 / 0.9867. S+A 69.773 / 69.656 / 68.549 ms; ratios 0.9983 / 0.9802 / 0.9876.

Interpretation and code inspection
- The no-guard build is about 4.4% faster than the candidate on scalar T255 analysis and about 2.9% faster on spin-1 T511 analysis in this screen. It is about 0.7% faster on scalar T255 synthesis. This isolates a measurable cost associated with the `recombine_half` guard on these operations; no-guard remains around 2.6% slower than the old baseline on scalar T255 synthesis, so this screen does not attribute that synthesis difference to the guard. The candidate's scalar T255 synthesis and analysis each remain above the 2% diagnostic threshold in all three triples; the six-pair campaign is the stronger original control record.
- `nm -C` shows `recombine_half` inlined into `<rustsht::fft::RealFftPlan>::forward`. The candidate disassembly has per-result exponent extraction/checks and a conditional branch to the exceptional path (`candidate-forward.asm`, lines 224-237). Both candidate and no-guard code use packed 128-bit operations over real/imaginary parts of one complex value; neither shows vectorization across multiple frequency bins. The guard adds a branch and dependencies, but this inspection does not establish that it blocks wider vectorization.
- Ratios compare the old baseline, current candidate and a diagnostic build that differs from the candidate only by the guard removal. They help isolate the cost of this guard from the shared `inverse_series`/normalization refactor; they do not measure extreme-value correctness or constitute an acceptance decision.
