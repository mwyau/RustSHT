Grid and conventions
- Use `sht_gauss` with exact `nlat=L+1`, `nphi=2*(L+1)`, `mmax=L`, `mres=1`; these satisfy SHTns' documented Gauss constraint `nlat > lmax` and longitude constraint `nphi > 2*mmax`. `shtns_set_grid` accepts the exact counts. SHTns longitude starts at phi=0 and the grid setter has no phi0 argument; phi0 does not affect transform timing, and exact field matching can use coefficient phase shifts.
- SHTns `sht_orthonormal` uses the same orthonormal normalization family and includes Condon–Shortley by default. Do not add `SHT_NO_CS_PHASE` or `SHT_REAL_NORM` for the DUCC/RustSHT convention.
- `time_SHT.c` can be configured with `-gauss -mmax=L -nlat=L+1 -nphi=2*(L+1) -nth=q -transpose`; `-transpose` selects phi-contiguous storage (same row layout as RustSHT). `-vector` includes vector timings, and `-nogpu` disables offload. It uses `shtns_set_grid_auto` with the requested nonzero dimensions; for an exact controlled driver, call `shtns_create` followed by `shtns_set_grid` directly. It has no explicit phi0.
- RustSHT/DUCC `examples/python_perf_baseline.py` already accepts explicit `nphi` and `ntheta`, GL, full mmax, f64, phi0=0.37 and both synthesis/analysis; it prints paired numerical errors and timings for RustSHT and DUCC. Its backend choices are only `both`, `rust`, and `ducc`; it has no SHTns adapter. SHTns `time_SHT.c` is an independent timing/roundtrip harness, not a cross-framework comparison, and uses its own generated data.
- SHTns spin-vector convention is spheroidal/toroidal potentials S/T with `Vtheta = d_theta S + csc(theta)*d_phi T`, `Vphi = csc(theta)*d_phi S - d_theta T`, exposed by `SHsphtor_to_spat` and `spat_to_SHsphtor`. RustSHT/DUCC spin-1 STANDARD uses E/B coefficient channels and theta/phi map channels. S and T are not directly the same coefficient channels as E/B; an explicit l-dependent coefficient mapping/sign check against analytic fields is required before treating inputs/outputs as equivalent. SHTns' `-vector` timing can still measure whole vector-transform cost, but its default random S/T fields are not a matched numerical workload.
