# T720 production and cumulative candidate A/B

Both runs use RustSHT source `fbba7c39c1b8b5a2e13898611095666d783a3fe3`, Rust 1.99.1 / LLVM 23.1.1, runtime Pulp V3, and DUCC 0.42.0 at `42ce8ab5c5d79e0e2fd9af4a09c2ea4693520e1b`. Rust was compiled strictly for `x86-64-v3`. DUCC SHT sources used `-O3 -ffast-math -ffp-contract=fast -march=x86-64-v3`; the driver remained strict. GCC was 15.2.0.

The host was an AMD Ryzen 9 5950X, x86-64, with 16 physical cores, 32 logical CPUs and 96 GiB RAM. AVX2 and FMA were available; AVX-512 was not. q1 used one physical core and q8 used eight. The OS reported Linux 7.0.14-20-pve. Median/p10/p90 frequency was 4.342/1.746/4.691 GHz for production and 4.400/1.746/4.752 GHz for the cumulative candidate.

The same deterministic fixtures covered T720, `mmax=1,180,720`, odd-minimum and even-smooth longitude counts, analysis and synthesis, and q1/q8. Each row has three interleaved process pairs and 10 calibrated batches per backend/process. The outputs contain 24 rows and 72 Rust/DUCC numerical comparisons. `results.csv` records medians, p10/p90 ranges, batch counts, first-call timings, paired ratios, and numerical errors. Per-process diagnostic captures remain local.

The cumulative binary enabled `rustsht_scalar_analysis_fixed_simd_arrays`, `rustsht_packed_complex_pair_reduction`, `rustsht_indexed_analysis_pair_loop`, and `rustsht_scalar_analysis_direct_accumulation`; this source snapshot predates removal of the direct-output and indexed-loop candidates. Its warmed numerical outputs were finite and had maximum relative L2 error `1.841e-13` and maximum absolute error `3.742e-10`. Twenty-four cumulative worker samples reported a different first-call versus final analysis output at `mmax=180,720`: the first call used checked staged accumulation, while later calls could use direct output accumulation after the cached range proof. This accumulation-order difference is reported explicitly; all Rust/DUCC numerical comparisons passed.

Host summaries: production run-queue wait median/p90 `0.97% / 15.4%`; cumulative `0.48% / 10.1%`. The no-direct combined rerun is excluded because its host summary showed `13.7% / 67.5%` wait median/p90. Do not use that run for attribution. The standalone report writer assumes the full historical sweep includes T1536/T2048/T3072, so this focused selection was run with `--no-report`; the CSV here is the machine-readable aggregate.

Reproduction: set `DUCC_SRC` to the pinned checkout, `DUCC_REVISION=42ce8ab5c5d79e0e2fd9af4a09c2ea4693520e1b`, `CXX` to GCC 15.2, and `CARGO_TARGET_DIR` to a clean target directory. Build the DUCC adapter once with the production Rust flags. For the candidate, rebuild the Rust example with the four `--cfg` flags listed above and use the same DUCC executable with `--skip-build --no-report`; use distinct result directories for each run.
