# Matched RustSHT–DUCC synthesis profile

**Checkpoint:** RustSHT `c5f102112bc4c3f0cabd485d1154c38f8d2dbc9d`; DUCC source `80388904b8cfc32400ba84af8a6a45aabfe60f86` (installed comparison package ducc0 0.41.0). Both builds used Rust 1.99.0 or g++ 15.2.0, `-O3`, debug symbols, frame pointers and x86-64-v3 / AVX2-FMA on a Ryzen 9 5950X (16C/32T). Rust used `-C target-cpu=x86-64-v3`; DUCC used `-march=x86-64-v3 -mtune=generic`.

## Method and agreement

Compared f64 scalar GL synthesis at T720/mmax720/721×1442 and T300/mmax150/301×603, `phi0=0.37`, q1/q8. Both used identical packed coefficients generated by the same integer formula. Rust reused one plan and workspace per cell; DUCC reused coefficient, Legendre and map buffers for direct `alm2leg` and `leg2map` calls. Each cell had one warmup and five timed calls; Rust and DUCC full-synthesis calls were interleaved in persistent processes. Full DUCC `synthesis_2d` has no reusable public plan and includes its own setup. Its reported setup and Rust plan/workspace construction are therefore separate and are not included in the timed transforms.

The scalar ordered Rust path ran for all cells; the normal finite inputs did not take its safety fallback. q1 map comparison gave T720 max absolute error `1.87e-12`, relative L2 `8.66e-15`; T300 max absolute error `2.95e-13`, relative L2 `3.59e-15`.

## Follow-up after the largest measured hotspot

On the same `c5` source, a narrow Rust change skips recurrence-state updates for SIMD groups where no lane exceeds `sht_ftol`, and checks the scale-epoch reduction only after a lane rescales. This follows DUCC's `rescale()` early return and `iter_to_ieee()` reduction condition while retaining overflow checks for changed lanes. The q1 full-synthesis median improved from `31.098` to `26.741 ms` at T720 and from `3.523` to `3.094 ms` at T300. q8 medians overlapped the earlier ranges, so no q8 gain is concluded.

## Stage measurements

Rust phases came from the existing test-only transform observer. DUCC stages were measured through its direct C++ API. These boundaries are close but not identical: Rust's Legendre phase includes spectral accumulation/scatter, while DUCC `alm2leg` produces the intermediate spectrum. RustFFT and DUCC `leg2map` are the corresponding inverse-FFT/map stages.

T300 q1 shows the same scaling pattern: initialization `0.209/0.064 ms`, insignificant prefix `0.555/0.012 ms`, ordinary recurrence `1.050/1.074 ms` (Rust/DUCC). Component timers were added only at order, vector or active-batch boundaries; q8 component sums are not compared because DUCC's diagnostic atomic counters contend across workers. Rust q8's coarse observer measured a `0.221 ms` order-major spectrum scatter at T720. This is too small to explain the full q8 gap; the remaining excess is in the parallel Legendre/order phase, not the FFT.

Rust plan/workspace construction was 0.15/6.77 ms (T720 q1), 0.07/8.38 ms (T720 q8), 0.05/1.53 ms (T300 q1) and 0.05/1.58 ms (T300 q8). DUCC driver coefficient-input plus geometry/buffer setup was about 2.00/0.05 ms at T720 and 0.28/0.03 ms at T300. These include different work and are not a setup-speed comparison.

## Hotspots, evidence and next fixes

1. **Initialization and scaled-prefix work are the largest measured Rust-side excess.** At T720 q1 the combined Rust timer is `10.08 ms` versus DUCC's `0.60 ms`; T300 shows `0.764 ms` versus `0.076 ms`. The timer boundaries are close but not identical: Rust's bucket also includes scaled accumulation. Skipping empty rescale updates reduced full q1 synthesis by 14% at T720 and 12% at T300 in the follow-up screen, but Rust remains slower overall.
2. **The q8 Legendre/order path is the next gap.** The initial q8 Rust Legendre phase was 1.59× DUCC at T720; Rust's explicit spectrum scatter took about `0.22 ms`, too little to explain the full difference. Current full q8 ratios remain about 1.6× at T720 and 1.9× at T300, but sample variability prevents a firm change conclusion. Separate scheduling and memory-layout costs during scalar analysis/spin-1 integration.
3. **Ordinary recurrence is a smaller q1 gap.** T720 was `13.66/12.90 ms` Rust/DUCC; active-ring packing and coefficient preparation were faster in Rust. Both optimized AVX2 bodies contain YMM FMA and coefficient broadcasts (`alm2map_kernel` in DUCC and the Rust `ScalarOrderedSynthesis` V3 path). This evidence does not support attributing the gap to Rust language overhead.

`perf stat` and `perf record` both failed to open CPU events because `perf_event_paranoid=4`; no system setting was changed. Therefore cycles, instructions, cache misses, IPC and sampled function costs are unavailable. Static disassembly confirmed AVX2-width YMM/FMA generation but cannot attribute time to instructions. The first T720 q8 DUCC sample and the T300 q8 samples varied substantially; medians are reported, and the short screen cannot distinguish host jitter from scheduling variation. No competing benchmark was run.
