# Native-f32 spin-1 analysis preweighted-channel screen

## Decision

This isolated B3 candidate removes repeated per-degree scale and cosine
multiplications by preweighting the two spin-analysis scalar-channel
coefficient sets at each scale epoch, then accumulating both channels in one
native-f32 SIMD loop. It reduces source-parent f32 time by 9.3%, 17.1%,
31.4%, and 36.2% in full q1/q8 and reduced q1/q8, respectively. It still misses
the interim 2.0x matched-f64 target in every cell: the exact three-pair median
ratios are 4.231x, 3.836x, 3.636x, and 3.324x. Rust/DUCC is 5.384x, 5.022x,
4.541x, and 4.201x. Stop this bounded loop-fusion attempt; do not repeat it
unchanged.

The measured bottleneck is still unexplained below whole-call level. The exact
AVX2 loop executes eight packed-f32 FMAs per eight latitude lanes, reading eight
preweighted coefficient streams. The full symbol also contains 21 YMM
instructions with stack operands, including coefficient loads and scratch
stores/reloads. This is not evidence of zero spills, and the timing share of
scale/exponent transitions, hard-lane work, stack traffic, FFT, or scheduling
has not been separated. Hardware event profiling was unavailable in this
environment. Further B3 tuning needs a different measured execution mechanism.

The candidate passed the listed analytic/reference, adjoint, polar, workspace,
and code-quality checks. It matched its parent byte-for-byte in two checked
T720 output cells. Random-map comparison to DUCC gives relative L2 about
`1.85e-5` full and `2.17e-5` reduced. Neither check is independent complete-array
high-degree accuracy acceptance. Keep this candidate isolated.

## Reproduction

Apply the patch to the parent source, then build the native-f32 worker and the
packaged diagnostic f64 worker:

```sh
git checkout db88a867643d9772e1be71daf7edf3be581137b2
gzip -dc reports/archive/experiments/native-f32-spin1-analysis-preweighted-2026-10-30/candidate.patch.gz | git apply
RUSTFLAGS='-C target-cpu=x86-64-v3 -Aunexpected_cfgs' cargo build --release --features parallel --example ducc_f32_full_transform_parity
RUSTFLAGS='-C target-cpu=x86-64-v3 -Aunexpected_cfgs' cargo build --release --manifest-path reports/archive/experiments/native-f32-spin1-analysis-preweighted-2026-10-30/f64-worker/Cargo.toml
```

Build the pinned DUCC native-f32 worker with the repository's DUCC 0.42.0
benchmark recipe. Set `RUSTSHT_B3_SCREEN_DIR`, `RUSTSHT_B3_RUST_F32`,
`RUSTSHT_B3_RUST_F64`, and `RUSTSHT_B3_DUCC_F32` to a fresh scratch directory
and those three binaries, then run this package's `benchmark.py`. It regenerates
the fixtures, runs the interleaved screen, and writes `t720-3pair.json` to the
selected screen directory.

The archived candidate does not promote production dispatch. Its recoverable
source patch and isolated branch are diagnostic evidence only.
