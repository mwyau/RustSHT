## Dispatch and work layout

For exact GL T720 full-mmax q8 (`ntheta=721`, `mmax=720`), the current source cannot take `hemisphere::synthesize`: `spin1_hemisphere_worker_count` ends at `lmax=511`. At capacity 8, workspace ring groups are 64 rings; the GL T720 spin-1 fine-group selector returns 32, so both values are below 721. The spin-1 coefficient-cache gate checks the workspace value, while the ordinary ring route would use 32; the following order-major route supersedes those groups. Its eligibility count is `ceil(721/8)=91`, above the required 16, and its task tile is one order (`SPIN1_ORDER_MAJOR_TILE=1`). Each queued call therefore has `ring_start=0`, `ring_end=721`, `order_start=m`, `order_end=m+1`, and compact `spectrum_len=1`.

That one-order GL/full-mmax shape satisfies `prepared_component_attempted` in the fast scalar segment: the contiguous-order predicate does not require q1, and the full-grid symmetry condition is `0+721=721`. The call first converts the E/B order into two scalar coefficient rows, checks finiteness, then `try_synthesize_spin1_prepared_component_order_from_workspace` checks input range/subnormal safety and prepares pair coefficients. On acceptance, the reflected adapter runs one scalar SIMD recurrence per output component over northern latitudes and reconstructs both hemispheres. Polar and any declined work stay on the established fallback. This makes the reflected adapter a source-established eligible path for q8, but the exact number of attempts, successes and fallback updates is absent from existing q8 evidence; do not infer that all 721 orders succeeded.

The T720 coefficient-row estimate is 16,657,984 bytes. Since it exceeds the 4,000,000-byte local-conversion threshold, this route converts each order into worker-local coefficient rows instead of building the whole table. It also misses the 16,000,000-byte fused-local-preparation gate. For finite rows, source flow therefore converts spin coefficients, scans them for finiteness, then scans them again for safe magnitude/subnormal values before pair preparation. Those are two distinct order-length passes with O(T²) total work; their exclusive instruction cost is unresolved.

For each of 721 orders, `synthesize_spin1_order_major_queue` clears two 721-element complex rows, calls the one-order recurrence, and scatters Q/U values to unique columns of ring-major spectra. The clear pass is 16,634,912 bytes and the scatter pass is the same: **about 33.27 MB of extra explicit stores per T720 transform**, apart from recurrence writes and the transform's initial spectrum reset. Inactive output entries are already zeroed globally. This traffic is source-derived; no elapsed-time share or cache cost has been measured. Any selective-write path must preserve initialized accumulation ranges and whole-order rollback if a checked adapter declines after partial output.

Pinned DUCC's `allocate_leg` uses m-major backing for parallel synthesis, returned through a transposed logical view. Its `alm2leg` converts spin-1 coefficients once per order with `spin1to0`, then calls `inner_loop_a2m` for each scalar component; `fill_a2m` packs active rings, `calc_alm2map` runs the scalar recurrence, and `extract_a2m` writes results by order. This gives a concrete storage-layout contrast with Rust's worker-row clear and scatter. The arithmetic still needs matched active ring × degree-pair × component counts before comparing kernel costs.

## Existing q8 evidence and limits

The accepted historical Plan 16 order-major experiment on exact GL T720 full q8 reported Rust 19.509 ms on the old group route, 15.199 ms after order-major dispatch, and DUCC 5.903 ms (2.58× for the new route on that dated build). Its phase probe put Legendre recurrence plus spectrum work at 19.678→12.579 ms; summed worker factor preparation fell 13.518→1.330 ms, cache preparation was 1.883→1.885 ms, and FFT/writeback was 1.318→0.929 ms. This identifies recurrence/spectrum as the largest measured stage in that old comparison, but it is not a current-HEAD measurement. Current [PERFORMANCE_STATUS.md](../PERFORMANCE_STATUS.md) records newer CC T720 q8 PASS cells; the GL T720 q8 row remains historical.

The source-matrix GL T320 oversampled spin-1 q8 profile recorded 605.134M Rust Ir and 226.425M Ir for a different DUCC source build. That route used grouped-ring recurrence, had no active-work normalization, and did not change under the scalar ordered inlining candidate. It cannot establish T720 exact-q8 costs. Conversely, exact GL T720 q8 can attempt the prepared-component adapter, so the T320 result does not show that this route misses the SIMD-inline boundary.

For GL T320 oversampled q8, the present f64 scheduler has a concrete coarse-grain concern. With `LATITUDE_BLOCK_SIZE=128`, 640 rings produce five base blocks; the workspace grouping rule halves the one-block group to 64 rings, giving ten groups. The fine-group exception is exact-GL-only, the coefficient-cache/dynamic-queue gates are false, and f64's `prefers_fine_spin1_synthesis_groups()` default is false. The static iterator consequently uses `with_min_len(ceil(10/8)) = with_min_len(2)`, which permits at most five Rayon leaves for ten items. This is a **source-derived upper bound on simultaneously available group tasks**, not proof that only five workers ran: task execution and occupancy need worker evidence. It is a credible q8 scaling hypothesis given the existing 5.7× timing gap, but the source-matrix host was shared and the old profile did not record active workers.

At the other end, exact GL T720 q8 takes the one-order queue and not the ring-group scheduler. Its existing route stages each order through worker-local Q/U rows: clearing and scattering 721 complex values for each of two channels costs about 33.27 MB of explicit stores per transform. The global spectra were already zeroed. This is source-counted traffic, not measured cache or elapsed cost; direct unique-order output would need to preserve zero inactive cells and reset a partially written order before fallback. DUCC's parallel layout is m-major behind a transposed view and its `alm2leg` prepares spin-1 scalar coefficients once per order before its inner recurrence, so the staging difference is plausible but not yet an apples-to-apples store-cost comparison.

The existing scalar inlining change must also be interpreted by route. `PreparedComponentBatch::with_simd`, `synthesize_batch`, and `synthesize_ordinary_suffix_two_vectors` are marked `inline(always)` in the audited source. The T320 oversampled q8 profile shows that this prepared-component kernel is not entered by the grouped spin-1 route: its Ir and top AVX2 helper counts were unchanged by the candidate. This is **not** evidence against AVX2 inlining inside the exact-T720 prepared-component route or the hemisphere kernel. The accepted T1023 q1 disassembly reports a direct four-lane YMM ordinary loop with one live coefficient-vector spill, but it does not establish executed q8 PC cost. Do not add another inline attribute without an exact q8 PC and generated-code target.

## Ranked hypotheses (not production changes)

1. **Prepared scalar recurrence code generation.** Historical GL T720 q8 phase evidence put recurrence plus spectrum at 12.579 ms after the order-major change, the largest reported stage. Current q8 uses the same source-level `PreparedComponentBatch` / `synthesize_batch` path as the accepted reflected q1 route when preflight accepts; both `with_simd` and `synthesize_batch` are `inline(always)`. The T1023 q1 disassembly shows four-wide YMM FMAs and one live coefficient-vector spill, but that is not q8 dynamic attribution; see the [T1023 q1 report](T1023_Q1_ROOT_CAUSE.md) for the existing PC evidence. First map q8 executed PCs to this inner loop and distinguish coefficient spills from intentional recurrence scratch. Any candidate should target an observed q8 spill/load or dependency and predict its Ir reduction; do not add generic inlining.
2. **Recompute of an order-invariant threshold for every component batch.** `PreparedComponentBatch::with_simd` calls `power_lower_limit(m)` for each dispatched batch; the helper computes `exp(-400 ln(2)/m)` for `m>0`. The ordinary reflected `ScalarOrderedSynthesis` path computes the same value once per order and reuses it across latitude batches. At T720, 361 northern lanes and the 256-lane batch cap mean at most two batches per component, so the unoptimized source call graph permits up to four threshold evaluations per order in the prepared adapter instead of one (at most 2,880 versus 720 over 721 orders). LLVM may inline or hoist this pure order-invariant expression; actual optimized call counts and Ir are unresolved. A bounded follow-up could compute the identical f64 value once per order and pass it through the two component batches. First confirm the optimized PC/call count and Ir; the source difference alone does not establish a meaningful runtime gain.
3. **Worker output clear and scatter.** The source performs about 33.27 MB of explicit q/u stores per T720 transform across per-order row clearing and scatter. Attribute their PCs before considering a writer path that targets the unique global order directly. Such a path must preserve zeroed inactive rings and clear a partially written order before checked fallback; store count alone does not establish a material runtime benefit.

4. **Oversampled q8 task granularity.** For GL T320 oversampled q8, source bounds the static group iterator to at most five leaves, while the request is eight workers. This could be a large wall-time cause even if each paired SIMD update is competitive. The test is a read-only source prediction; existing timing and instruction totals do not reveal actual worker occupancy. If later profiling becomes available, collect worker IDs and per-worker group time before changing grain or enabling a dynamic queue.

The two order-local coefficient checks are another smaller O(T²) source opportunity: finiteness is scanned after conversion, and the adapter then scans its active suffix for safe magnitude/subnormal values. Their instructions should be attributed separately before combining predicates; all decline and fallback checks must remain.
