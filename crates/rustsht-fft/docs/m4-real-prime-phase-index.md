# Real general-prime phase index lookup

The real general-prime passes previously advanced each root phase with a
conditional modular update inside the coefficient loops. Plans now store the
phase indices for each frequency and branch when `6 <= radix < 135`. The table
contains `(frequency * branch) mod radix`; it is generated by repeated
addition, uses one byte per entry, and its `radix * radix` allocation is
checked. Other radices keep their existing paths. The lookup adds immutable
plan data without changing execution scratch. The benchmark compares baseline source `d89284bbb0fe28e3e989d7a88d565c7500f4bf14`
with the candidate change in `real_multipass.rs` (SHA-256
`daa97be30a15476c897e6aca0709c48f6d662ac0bb833ebe228b51b7efdb6c06`). The
baseline and candidate executable SHA-256 hashes are respectively
`b39ef0163ecc60eb1135e591d92e9d97938bd57791e9d34d66cc24526cf2441d` and
`1e4e0c0f0cb6de041fc9ca4d03e8af686e758e6a9bcdbff7891580f8c21d5c09`. Both used Rust 1.99.0, Cargo's bench profile (`opt-level=3`), and no custom
`RUSTFLAGS`, LTO, or CPU target. The host was an x86-64 CPU; processes
were pinned to logical one CPU core while another workload was active, so absolute
times are provisional. Six interleaved process pairs ran the native f64 `bench-native-real N 1 32`
harness. Each operation timing is the median of seven timed samples after one
warm-up. The 32-row column reports time per transform. Speedup is the median
of the six within-pair baseline-to-candidate ratios. Plan and workspace
creation were measured separately; reusable workspace size did not change.

| Length | Operation | Rows | Baseline | Candidate | Speedup |
|---:|---|---:|---:|---:|---:|
| 1025 | R2C | 1 | 14.37 µs | 12.34 µs | 1.166× |
| 1025 | R2C | 32 | 14.30 µs | 12.31 µs | 1.162× |
| 1025 | C2R | 1 | 14.29 µs | 12.45 µs | 1.144× |
| 1025 | C2R | 32 | 14.35 µs | 12.43 µs | 1.157× |
| 4097 | R2C | 1 | 235.94 µs | 228.40 µs | 1.034× |
| 4097 | R2C | 32 | 238.75 µs | 231.88 µs | 1.034× |
| 4097 | C2R | 1 | 246.45 µs | 238.06 µs | 1.036× |
| 4097 | C2R | 32 | 250.39 µs | 241.34 µs | 1.036× |

The candidate won all six pairs in every operation and row-count cell. Median
plan creation at N=1025 increased by 0.80–0.96 µs; at N=4097 it changed by
less than 0.52 µs. Workspace sizes remained 28,944 bytes at N=1025 and
129,728 bytes at N=4097. The N=1025 execution savings exceed the plan cost
after the first transform. The N=4097 gains are smaller and should be treated
as a screening result on this shared host. Raw process records, including plan and workspace timings, are in
[`m4-real-general-prime-phase-index-process-samples.csv`](../benches/results/m4-real-general-prime-phase-index-process-samples.csv).
