**Startup reading:** this file, [active plan](plans/f64-ducc-parity-all-cases-2026-10-24.md), [accepted-results ledger](PERFORMANCE_STATUS.md), and the latest few entries of [rolling checkpoints](reports/PROGRESS.md). **Performance method:** reproduce one gap on the exact benchmark/DUCC revision, profile the actual route and expensive loop, try one bounded mechanism, and compare interleaved exact-parent/candidate/DUCC whole transforms. Include focused numerical, adjoint, extreme, scratch poison/reset, poles, phase/Nyquist and affected-thread tests. Accept only stable improvements without material regressions; otherwise revert and change hypothesis. Do not build another generic profiling framework or run a full benchmark matrix after each edit.

**Git checkpoints every 10–12 minutes of active work.** Record meaningful results briefly in `reports/PROGRESS.md` (at most five rolling checkpoints, each with UTC, SHA, exact case, outcome, tests run and next step). Push compilable, known-safe intermediate code as `wip(perf): ...`, clearly labeled unvalidated. Keep unsafe, uncompilable or known-incorrect edits local/test-only; instead push a substantive progress checkpoint. Fetch/reconcile before pushing; for long uninterruptible tests, checkpoint just before and immediately after. Do not invent empty commits or interrupt heavy measurements merely to satisfy the interval.

**Agents:** Luna Max owns source changes and decisions. No Sol. At most one bounded Luna subagent; avoid concurrent CPU-heavy benchmarks. Keep the existing session active across milestones and blockers. Report blockers, preserve work, then pursue the next safe task. Update `PERFORMANCE_STATUS.md` only for verified measurements or a corrected comparison.
