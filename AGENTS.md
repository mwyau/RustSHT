# RustSHT agent instructions

**Only active implementation plan:** [plans/11-ducc-equivalent-scalar-analysis.md](plans/11-ducc-equivalent-scalar-analysis.md).
Read that plan and the current production source before acting. Explicit current owner instructions take precedence. Other plans, old reviews, handoffs and benchmark reports are **historical evidence or numerical references**, not competing agent goals. Do not preload them.

- **Scope:** implement and validate numerical improvements on `opt/sht-performance-parity`. Prefer one source-grounded change at a time; avoid speculative SIMD tuning, unrelated FFT work, broad performance campaigns and new dependencies.
- **Numerics:** preserve the Rust API, independent `S/A/S*/A*` operators, GL/CC/F1, f32/f64, spin 0–4, correct scaling/phase/weights, subnormal and extreme-value safeguards, SIMD tails, serial/parallel behavior and checked fallbacks. Verify against pinned DUCC **and** analytic/adjoint tests; never relax tolerances for speed.
- **Implementation:** stable Rust, portable runtime Pulp SIMD and bounded caller-owned scratch. Neutral RustSHT source names, correct GPL-2.0-or-later and translated DUCC attribution. Archive demonstrably retired prototypes; do not retain layers of competing kernels.
- **Evidence:** measure equivalent work with matched release builds; identify the actual SIMD code path and report numerical errors and uncertainty. No arbitrary truncation-specific or percentage-speed targets. Preserve historical reports and code. Keep local host/process/PSI logs and raw disassembly untracked; record concise reproducible findings.
- **Workflow:** at most one Luna benchmark-only subagent, no Sol reviewer unless the owner changes this. Run formatting, relevant Clippy, release tests and no-default-features tests, with Python tests if bindings change. Before pushing: check worktree, fetch, reconcile concurrent commits safely, validate, push only to the feature branch and verify remote HEAD. Never force-push or touch `main` without authorization.
