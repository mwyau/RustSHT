# Native-generic transform architecture inventory

This is the Phase 0 source map for the active [M6 implementation plan](../plans/m6-ducc-parity-hotpath-cleanup-2026-10-27.md). The production tree is still transitional: GL scalar synthesis has an f64 order-major kernel, while a measured subset of public f32 scalar synthesis uses a temporary f64 child plan. The isolated native-generic candidate is experimental and has not replaced production dispatch.

| Classification | Current source | Disposition |
|---|---|---|
| **1. Shared mathematical algorithm to retain** | `src/legendre/scalar_paired/synthesis.rs`; shared recurrence, symmetry, coefficient and channel-conversion code in `src/legendre/mod.rs`, `src/transform/spin/synthesis.rs`, and `src/transform/spin/hemisphere.rs` | Preserve the scalar and spin conventions, degree recurrences, reflected-ring pairing, parity, phases, adjoints, and exceptional-range behavior. Consolidate execution around the shared generic algorithm as each family is replaced; keep independent numerical reference tests. |
| **2. f64 optimized algorithm to genericize** | `src/legendre/scalar_ordered.rs`, `src/legendre/scalar_ordered/kernel.rs` | The order-major GL synthesis schedules, north/south reflected work, sectoral initialization, scaled prefix, ordinary SIMD suffix, even/odd accumulation, and disjoint Fourier-order output define the target mathematical control flow. Today the kernel still uses f64 arrays, `Complex64`, f64 SIMD lanes, and f64 scaling constants. `ScalarOrderedScratch<T>` and `DisjointSpectrumOutput<T>` already provide generic storage/output foundations. |
| **3. Necessary precision-specific arithmetic/SIMD leaf** | `src/legendre/numeric.rs`; typed implementations in `src/legendre/scalar_paired/synthesis.rs`; `LegendrePrecision` and `ShtScalar` implementations in `src/legendre/mod.rs`; `RealFftPlan<T>` in `src/fft/` | Keep native f32/f64 vector operations, lane widths, thresholds, scale increments, normalization and FFT. In particular, `LegendrePrecision` has different f32/f64 exponent increments; do not copy f64 thresholds or exponent behavior into f32. `FusedSynthesisPrecision` is an existing typed SIMD pattern that can inform a narrower ordered-kernel abstraction. |
| **4. Obsolete f32 transform implementation/fallback** | f32-specific callbacks and legacy general recurrence routes in `src/legendre/mod.rs`, `src/legendre/scalar_paired/`, and `src/legendre/spin*`; fallback routing in `src/transform/scalar.rs`, `src/transform/spin/synthesis.rs`, and `src/transform/spin/hemisphere.rs` | Treat as replacement debt, not compatibility contracts. Remove a route only after its operations are covered by the shared native algorithm and numerical exceptional handling is retained there. The present f32 general routes remain active for operations the isolated ordered candidate does not yet replace. |
| **5. f32-to-f64 conversion sidecar to remove** | `ShtPlan<f64>` child-plan construction in `src/plan.rs`; `F32InternalScalarSynthesisWorkspace` in `src/workspace.rs`; input promotion, output narrowing and range guards in `src/transform/scalar.rs`; `F32_INTERNAL_SCALAR_SYNTHESIS` dispatch in `src/legendre/mod.rs` | Temporary production path for two GL T720 scalar-synthesis geometries. Delete it after native generic synthesis satisfies numerical acceptance and gives a credible production improvement. Do not expand it to other transforms. |
| **6. Tests and benchmarks to adapt or archive** | `src/legendre/scalar_ordered/tests.rs`, `src/legendre/numeric/tests.rs`, `src/legendre/scalar_paired/**/tests.rs`, `src/transform/tests.rs`, `tests/`, `scripts/benchmark_ducc_f32_native.py`, `scripts/benchmark_ducc_full_transform_parity.py`, and the M6 evidence in `reports/` | Keep independent analytic, adjoint, exceptional-value, subnormal, workspace-reset, and API tests. Add shared-kernel f32 cases without weakening existing checks. Benchmark each native f32 cell against the exact production parent and pinned DUCC 0.42.0; label f64-recurrence diagnostics separately and archive rejected candidates with source provenance and numerical caveats. |

The plan and [per-cell ledger](../reports/DUCC_PARITY_M6.md) remain the execution and measurement sources of truth. This inventory does not establish that the generic candidate is numerically accepted or at DUCC parity.
